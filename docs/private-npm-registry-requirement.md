# 需求说明：公司内部私有 npm 源

| 项目 | 内容 |
| --- | --- |
| 提出方 | 产品部门 |
| 面向 | AI 团队 / IT 运维 |
| 优先级 | 中（有临时方案在跑，但不可长期依赖） |
| 一句话诉求 | 请提供一个**公司统一维护的私有 npm 包源**，用于分发内部 DSH 插件 |

---

## 1. 我们要解决什么问题

我们做了一个 DSH 插件「场景工作台」，需要发给公司同事使用，并且要能持续更新。

现在没有正式的包分发通道，只能靠**人工拷贝代码、逐台改配置**。一旦插件更新，要么挨个通知重装，要么同事用着旧版本也不知道。

这跟公司内部其它软件的分发方式不一致——那些都有统一的安装包/更新通道。

## 2. 需求内容

请提供一套私有的 npm 包源（内部 registry），满足以下 6 点：

| # | 需求 | 验收标准 |
| --- | --- | --- |
| 1 | 稳定的访问地址 | 内网任何机器能 `curl` 通，长期不变 |
| 2 | 支持公司 scope 的私有包 | 能发布 `@runner-corp/*` 形式的包 |
| 3 | 发布权限 | 产品部门 1–2 个账号可发布，不开放给所有人 |
| 4 | 读取权限 | 全员可读，**不需要登录**（降低使用门槛） |
| 5 | 历史版本保留 | 已发布的版本不能被清掉，否则用户重装老版本会失败 |
| 6 | 定期备份 | registry 数据目录纳入备份，机器故障后能恢复 |

## 3. 现在是怎么将就的

我们在测试服务器 `crm-ex-test02`（192.168.156.203）上用开源软件 **Verdaccio** 临时搭了一个，端口 9001，已经验证可行，同事可以正常安装。

**但这不能作为长期方案**，原因：

- 测试机上跑业务服务，别人重装/调整时容易被清掉
- 没有纳入备份，机器故障后所有已发布版本都会丢
- 没有权限体系，谁都能发也能删
- 测试机的生命周期不由我们控制

## 4. 建议方案与工作量

如果公司已有 Nexus / Artifactory，直接开一个 npm 仓库即可；没有的话，用 Verdaccio（Node 写的轻量服务，我们已在 Rocky 9 + Node 22 上验证过）。

我们这边可以直接提供：

- 可用的配置文件（Verdaccio 配置、systemd 单元、nginx 反代片段）
- 一套部署与回滚脚本（已在测试机跑通，含 SELinux / 防火墙处理）
- 发布工具（一条命令发版）

**预计实施工作量**：安装服务 + 配反向代理 + 开权限 + 验证，半天到一天。

## 5. 预期收益

- **对产品部门**：发版从「人工拷贝」变成「一条命令上传」，同事打开插件就能收到更新提醒
- **对公司**：内部插件有了统一分发通道，后续其它部门做 DSH 插件可以直接复用，不用各自再造
- **降低支持成本**：版本不一致、装错包这类问题会大幅减少

## 6. 后续规划

目前是 1 个插件。按现有架构，后续接入 TAPD 等业务系统的插件可以直接复用同一套通道——**注册一次，长期受益**。

---

## 附：需要确认的两件事

1. 公司是否已有可用的私有源（Nexus / Artifactory / 其它）？如果有，我们优先接进去，不再自建。
2. 开放 scoped 包发布是否需要走安全或合规审批？
